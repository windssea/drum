# 《鼓浪回击》港口节拍队原声

整套音乐取自三次 Google Lyria 3.5 生成的立体声录音。铜管领奏、拨弦、贝斯和船员唱答构成曲子的主题；常速、慢练、留白、三连及胜败尾句都剪自这些演出。每场战斗固定为 4/4 拍、四轮、共 16 小节。

## 上课时听什么

| 课程 | 伴奏 | 给鼓手的听觉线索 |
| --- | --- | --- |
| 第 1 组基础拍 | `battle` | 完整乐队和鼓组。跟低音找一拍，再听亮一点的反拍与铜管应答。 |
| 第 2 组摇滚变奏、第 3 组切分与细分 | `battle_space` | 同一次演出的贝斯、人声及其他乐器分轨重混，抽出鼓组。Half-time 的重军鼓、一落雷鬼的第三拍由玩家演奏。 |
| 第 4 组三连摇摆 | `battle_shuffle` | 来自另一段有清晰三分格的演出，主要脉冲间可以听见三连音的第二、第三格。去掉鼓组后，跟低音数四拍，辨认旋律中的长短音。 |
| 胜利 | `victory` | 彩色铜管尾句与乐队最后一击；源录音约 58.77 秒处的重音落在结算镜头约 0.94 秒。 |
| 再挑战 | `defeat` | 从另一首录音中取较低乐句，收暗高音，让贝斯与房间的余响先后消失。 |

提示词要求 D–F–A–G 的四音动机、中文短喊和小节间的唱答。实际配器、和声与词句由 Lyria 演唱和演奏。教学中的示范鼓仍由游戏按谱单独触发。

## 从录音确定下拍

三份原始输出都有自己的速度。我们测量音频中的低频包络、分频起音和周期性，用 Beat This! 的拍点分析交叉检查，再选取下一轮可以自然接上的下拍。原曲里的速度文字只作为演奏提示。

| 编配 | 源录音的实测节奏与编辑点 | 游戏中的拍点 |
| --- | --- | --- |
| 标准、留白 | 直拍演出的主要起音约每 0.400 秒一次，以相邻两拍合计 0.800 秒作为训练主拍。先取 0.046 秒起的 48 个训练主拍，再取 44.846 秒起的 16 拍末段。 | 两速各自从原录音等音高变速，四轮分别在第 0、16、32、48 拍进入。 |
| 三连 | 另一份演出的三分细分约 0.1667 秒，每 0.500 秒数一个主拍。截取 3.696、15.696、31.696、55.696 秒起的四个乐段，各用 16 主拍，保留出港、应答、紧张过门和返场。 | 每个主拍拍长为 625 毫秒或 833.333 毫秒。三分格分别为 208.333 毫秒或 277.778 毫秒。 |

标准版与留白版用相同剪点，三连版的选择依据是实际演奏的细分。两份留白母带将原录音以 HTDemucs 分为鼓、贝斯、人声、其他乐器四轨，再以贝斯 0.89、其他乐器 0.78、人声 0.89 的线性增益混合。已分离的无鼓母带以 FLAC 归档。

## 重建与测量

安装 Node.js 与带 libvorbis 的 FFmpeg，在仓库根目录运行以下命令。构建读取归档录音，做时间伸缩、短淡入淡出、静态响度匹配与编码，无需再次调用线上模型。

```sh
node scripts/build-battle-score.mjs
```

Web 音轨从音乐开头播放。原生音轨在同一未压缩母带前加四拍静音，然后独立编码。每份文件为 48 kHz 双声道 Ogg Vorbis。

| 音轨 | Web 解码帧数 / 秒 | 原生解码帧数 / 秒 | 原生预备 | 标准 / 留白 / 三连综合响度 |
| --- | --- | --- | --- | --- |
| 96 BPM | 1,920,000 / 40.000 | 2,040,000 / 42.500 | 120,000 帧 | −16.5 / −19.5 / −18.8 LUFS |
| 72 BPM | 2,560,000 / 53.333 | 2,720,000 / 56.667 | 160,000 帧 | −16.6 / −19.5 / −18.8 LUFS |
| 胜利 | 88,800 / 1.850 | 同一音轨 | — | −14.9 LUFS |
| 再挑战 | 82,560 / 1.720 | 同一音轨 | — | −17.6 LUFS |

对六首主曲做解码后对齐验证，原生轨移除四拍前导后的抽样均匹配零帧偏移。把源录音与成品的低、中、高频瞬态包络按速度映射，在 193 个可可靠匹配的位置测得相对既定拍点的绝对编辑误差中位数为 2–3 毫秒，各曲第 90 百分位为 4.1–7.4 毫秒，最大为 10 毫秒。该项测量针对音频文件；触摸、MIDI 和声卡往返延迟需要在实机另测。[离线剪辑与母带脚本](../scripts/build-battle-score.mjs)
